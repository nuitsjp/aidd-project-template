<a id="mock-scope"></a>
## 2. モック駆動開発の適用範囲

採用先の製品で新設・変更する系列に適用する。配布物の固定データは `frontend/tests/fixtures/` に置く試験用で、仕様合意用モックではない。新しい仕様合意用データは対象系列に限定し、実処理接続後に削除・移動する。テスト用データによる合格と実処理の検証を区別する。

<a id="sources"></a>
## 3. 文書の役割

| 正本 | 内容 |

| 本書 | 配布元・固有差分・文書の役割・合意保護 |

既存の正本に収まる内容は文書を新設しない。経緯はGit、診断ログ・画像はリポジトリ外に置く。

<a id="agreements"></a>
## 4. 保護する合意

合意済みの責務分担・技術選定を維持する。サンプル個別のUI、受け入れ条件、Windowsでの動作は利用者確認前である。未実施の確認や架空のコミットを合意欄に補わない。採用先の仕様変更には標準の確認手続きを適用する。
