# UC-3. 新版を確認してアプリを更新する

主アクターは利用者。目的はデータを維持して新版へ移行すること。[実現パターン](../architecture.md#patterns)はUCP-2を外部インストーラーへ適用するものとし、アプリの終了後に結果が確定する点が異なる。

## 主成功系列 UC-3-M

1. 利用者が更新確認を指示する。Goが配布元の署名済み更新情報を検証する。
2. 新しい版があれば表示し、利用者が取得を指示する。
3. Goがインストーラーをローカルへ取得し、署名されたサイズ・ハッシュとの一致を検証する。
4. 利用者が適用を確認する。Goが稼働処理を確認し、取得物を再検証してNSISを起動する。
5. アプリが終了する。NSISが旧PIDの終了を待ち、更新して新版を起動する。

受け入れ条件: 対象アプリ・CPU・版・署名・ハッシュが不正なファイルを実行しない。取得／検証／起動失敗でアプリを終了しない。保存データを削除しない。実際の適用成功前に「更新完了」と表示しない。

初期配布物に実際の更新元・鍵は含めない。配布者が[発行手順](../project.md#release)で設定する。更新元未設定は明示し、成功の固定データへ置換しない。

## 合意状態

NSISとGo更新Serviceの方式は合意済み。個別の画面合意、Windows上の旧版→新版更新試験、未署名実行制御の確認は未実施。署名・破損・誤配布・取得・引き渡し制御は `internal/updates/service_test.go` で検証する。
