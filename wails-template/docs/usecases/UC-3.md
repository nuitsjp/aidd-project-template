# UC-3. 新版を確認してアプリを更新する

主アクター: 利用者。目的: データを維持して新版へ移行する。[実現パターン](../architecture.md#patterns)は UCP-2 の外部プロセス適用型であり、アプリの終了後に結果が確定する点が異なる。

## 主成功系列 UC-3-M（UI確認: 要）

1. 利用者が更新確認を指示し、Go が配布元の署名済み更新情報を検証する。
2. 新版があれば表示し、利用者が取得を指示する。
3. Go がインストーラーをローカルへ取得し、署名されたサイズとハッシュの一致を検証する。
4. 利用者が適用を確認し、Go が稼働処理を確認して取得物を再検証し、NSIS を起動する。
5. アプリが終了し、NSIS が旧プロセスの終了を待って適用後に新版を起動する。

受け入れ条件: 対象アプリ・CPU・版・署名・ハッシュが不正なファイルを実行しないこと。取得や検証、起動の失敗でアプリを終了しないこと。保存データを削除しないこと。実際の適用成功前に「更新完了」と表示しないこと。

初期配布物に実際の更新元や鍵は含めず、配布者が [発行手順](../project.md#release) で設定します。更新元未設定は明示し、成功の固定データへ置換しません。
