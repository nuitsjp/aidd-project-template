# UC-3. 新版を確認してアプリを更新する

- 主アクターと目的: 利用者がデータを維持して新版へ移行する（[プロジェクトの目的と範囲](../project.md) との対応）
- 前提: 配布者が [発行手順](../project.md#release) で更新元と公開鍵を設定している。初期配布物には実際の更新元や鍵を含めず、未設定は画面に明示する（成功の固定データへ置換しない）
- 主成功系列（UC-3-M、UI 確認: 要）:

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 利用者 / Go | 更新確認を指示する。Go が配布元の署名済み更新情報を検証する |
| 2 | システム / 利用者 | 新版があれば表示し、利用者が取得を指示する |
| 3 | Go | インストーラーをローカルへ取得し、署名されたサイズとハッシュの一致を検証する |
| 4 | 利用者 / Go | 適用を確認する。Go が稼働処理を確認して取得物を再検証し、NSIS を起動する |
| 5 | システム | アプリが終了し、NSIS が旧プロセスの終了を待って適用後に新版を起動する |

- 拡張（系列 ID の末尾は -X1 から。着手した系列のみ記載）:

| 系列 ID | 分岐点 | 条件 | 動作 | UI 確認 | 理由 |
| --- | --- | --- | --- | --- | --- |

- 受け入れ条件: 対象アプリ・CPU・版・署名・ハッシュが不正なファイルを実行しないこと。取得や検証、起動の失敗でアプリを終了しないこと。保存データを削除しないこと。実際の適用成功前に「更新完了」と表示しないこと。
- 実現パターンと逸脱: [UCP-3](../architecture.md#patterns) / 逸脱: なし

NSIS と Go 更新 Service の方式は合意済みです。個別の画面合意、旧版から新版への更新試験、未署名実行制御の確認は記入欄が埋まるまで未実施と扱います。署名・破損・誤配布・取得・引き渡し制御は `internal/updates/service_test.go` で検証します。
