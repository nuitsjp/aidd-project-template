# UC-3. 新版を確認してアプリを更新する

主アクター: 利用者。目的: データを維持して新版へ移行する。[実現パターン](../design/UCP-3.md)は UCP-3 です。

前提: 配布者が [発行手順](../project.md#release) で更新元と公開鍵を設定します。初期配布物には実際の更新元や鍵を含めず、未設定は画面に明示します。

## 主成功系列 UC-3-M（UI確認: 要）

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 利用者 / Go | 更新確認を指示する。Go が配布元の署名済み更新情報を検証する |
| 2 | システム / 利用者 | 新版があれば表示し、利用者が取得を指示する |
| 3 | Go | インストーラーをローカルへ取得し、署名されたサイズとハッシュの一致を検証する |
| 4 | 利用者 / Go | 適用を確認する。Go が稼働処理を確認して取得物を再検証し、NSIS を起動する |
| 5 | システム | アプリが終了し、NSIS が旧プロセスの終了を待って適用後に新版を起動する |

受け入れ条件: 対象アプリ・CPU・版・署名・ハッシュが不正なファイルを実行しないこと。取得や検証、起動の失敗でアプリを終了しないこと。保存データを削除しないこと。実際の適用成功前に「更新完了」と表示しないこと。

更新元未設定は画面に明示し、成功の固定データへ置換しません。
