# UC-1. メモを作成・編集して保存する

主アクターは利用者。目的は入力した内容を保存し、後から再び確認・編集できることである。[実現パターン](../architecture.md#patterns)はUCP-1。

## 主成功系列 UC-1-M

1. 利用者が新規作成、または一覧のメモを選ぶ。
2. システムが保存済みの内容を示す。利用者がタイトル・本文を編集する。
3. 利用者が保存を指示する。Goが入力を検証し、一体で保存する。
4. システムが保存結果と更新された一覧を示す。

受け入れ条件: 再読み込み・再起動後に保存内容を取得できる。同一IDの編集は件数を増やさない。再取得で未保存の下書きを上書きしない。

## 拡張 UC-1-X1

入力不正や保存失敗では下書きを維持し、原因を示す。未保存状態からの画面遷移・終了は確認し、取り消すと下書きへ戻る。保存処理中に破棄して移動しない。

## 合意状態

UI確認は要。個別の仕様・動作合意は未実施で、参照実装の案として提供する。提示コミットと利用者応答を作成済み扱いにしない。自動テストは `frontend/tests/e2e/usecases.spec.ts`、Goの保存検証は `internal/notes/service_test.go`。
