# ユースケース・シナリオの記述例

保守者が書き方を確認するための注釈付きの記述例です。生成先には配置しません。ルールの正本は [作成用スキル](../template/.agents/skills/usecase-docs/SKILL.md)（文書構造）と [モック標準](../template/docs/standards/mock-driven-development.md#discussion)（分割の基準と保存の手順）です。

例は React 拡張の参照実装にある「メモを作成・編集して保存する」を、そのまま転記したものです。ユースケース本体と主成功シナリオを載せています。拡張シナリオは主成功の `## 開始条件` の代わりに `## 分岐条件` を書き、分岐する操作・状態と条件を記載します。例の中の `../../project.md` などのリンクは、生成先での配置を前提としています。

## ユースケース（親）

`docs/usecases/メモを作成・編集して保存する/README.md`

```markdown
# メモを作成・編集して保存する

## 主アクター

利用者

## 目的

自身のメモを保存し、後から参照・編集する（[プロジェクトの目的と範囲](../../project.md) との対応）。

## 前提

利用者として識別されている（参照実装ではローカル用のユーザー選択）。

## 共通の受け入れ条件

保存・削除が成功した場合は、画面表示だけでなく SQLite への変更が確定し、再起動後も保持されること。別タブへは確定後の通知で一覧が追従すること。

## シナリオ

## 実現パターン

[UCP-1](../../design/UCP-1.md)
```

| 箇所 | 現れているルール |
| --- | --- |
| `# メモを作成・編集して保存する` | 見出しをディレクトリ名と一致させ、連番IDを付けない |
| `## 主アクター` | 1人の主アクターの1つの目的を1ユースケースとする（画面や API の単位で分けない） |
| `## 目的` | プロジェクト定義の目的との対応をリンクで示す |
| `## 前提`、`## 共通の受け入れ条件` | 任意項目。全シナリオに共通する事項だけを親に置き、シナリオに重複させない |
| `## シナリオ` | 子への個別リンクだけを1行に1つ並べる。所属する全シナリオを1回ずつ参照する |
| `## 実現パターン` | 設計（`docs/design/UCP-n.md`）へのリンクだけを置き、設計の本文は書かない |

## 主成功シナリオ

`docs/usecases/メモを作成・編集して保存する/scenarios/メモを作成・編集して保存する.md`

```markdown
# メモを作成・編集して保存する

- 種別: 主成功
- UI確認: 要

## 開始条件

利用者が自身のメモを作成または編集する。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | メモ一覧を開く | 自身のメモ一覧を表示する |
| 2 | 新規メモまたは既存メモを選択し、タイトル・本文を入力する | 選択したメモの内容を表示し、入力を受け付ける |
| 3 | 保存を指示する | 入力を検証し、SQLite へ更新を確定する。保存結果を表示し、一覧を更新する |

## 受け入れ条件

保存したメモの所有者・値・版が SQLite に確定し、保存結果と更新された一覧を確認できること。
```

| 箇所 | 現れているルール |
| --- | --- |
| `- 種別: 主成功`、`- UI確認: 要` | 選択値はこの2項目の書式どおりに書く。主成功はユースケースごとに1本 |
| `## 開始条件` | 主成功だけに書く。拡張では分岐条件に置き換える |
| `## 手順` の表 | `#`・`アクター`・`システム` の3列で書く。各行はアクターの操作と、それに対するシステムの振る舞いの組にする。主成功には条件分岐を含めない |
| `## 受け入れ条件` | 画面表示だけでなく、確定した状態（所有者・値・版）で期待結果を書く |

参照実装は全シナリオを記述済みの完成形です。実際の作業では、主成功を1本書いて完了させてから、拡張を着手時に1本ずつ追加します。未着手の拡張を先に並べることはしません。
