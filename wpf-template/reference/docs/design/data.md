# データ設計

テーブルと値の責務は [data.dbml](data.dbml) を正本とします。この設計はノートの参照実装用であり、採用先の製品仕様へ暗黙に引き継ぎません。

## 保存と型

通常の DB は利用者の LocalAppData の `<アプリID>/notes.db` に配置します。参照アプリの ID は `WpfNotesSample`、製品側は生成時に指定した名前です。`--data-dir` を指定すると、そのディレクトリの `notes.db` を使用します。開発時の起動は `dev-data/notes.db` の初期データを使います。配布先の exe とデータは分離します。

| DBML の論理型 | SQLite の型 | 用途 |
| --- | --- | --- |
| text | TEXT | ID、タイトル、本文、UTC の日時 |
| integer | INTEGER | 更新版 |

ID は新規保存時に発行します。版は新規 1、更新ごとに 1 増やし、更新・削除は取得時の版と照合します。日時は `DateTime.UtcNow` の `O` 書式で保存し、`RoundtripKind` で読み取ります。タイトルの重複は許容します。

一覧は更新日時の降順、同じ日時では ID 順で取得します。詳細は選択した ID で最新の値を取得し、対象が存在しなければ明示します。

## 入力値

タイトルは `Trim()` 後に 1〜100、本文は 0〜10,000 のテキスト要素数を許容します。文字数は .NET Framework 4.8.1 の `StringInfo.LengthInTextElements` で数えます。サロゲートペアと基底文字に続く結合文字は 1 要素です。ZWJ を含む絵文字列は画面上の 1 文字と一致するとは限りません。本文はトリムしません。

## 確定と移行

SQL 移行は `app/Infrastructure/Sqlite/Migrations/` に置き、本番とテストで同じ移行を使用します。適用した SQL と `PRAGMA user_version` の更新をトランザクション内で行い、現在のスキーマは 1 です。利用者の確認待ちはトランザクション外とし、保存・削除は短いトランザクションで確定します。版が一致しない操作は既存の行を変更せず、未確定の書込みはロールバックします。

DB 接続・保存の失敗時は原因を返し、既存データを消去して初期化し直しません。開発用の初期データ `dev-data/notes.db` を除き、実データと DB の WAL / SHM、依存取得物、ビルド成果物はリポジトリに保存しません。
