## 4. 実現方法と確認した事実

{{DESIGN_AND_EVIDENCE}}

今回の機能に必要な設計内容を記入します（仕様の詳細記述は避け、第3節のシナリオ ID に紐付けます）。

- **確認した事実**: 外部仕様や既存コードの調査結果（情報源・対象版・確認日・確認範囲）。仮定と明確に区別して記載します。

<a id="verification"></a>
## 6. 検証結果

{{VERIFICATION_RESULTS}}

検証結果は本節に直接記録するか、既存の実行記録（テストレポートやCIログ等）を参照します。

- **記録項目**: 対象コード・版、実行環境、モックまたは実処理の別、実行日、コマンド、合否結果、ログ等の根拠。
- **外部記録の参照**: 外部記録を参照する場合は、該当するシナリオ ID や受け入れ条件との対応、および判定に必要な補足のみを記載します（自動テスト結果の転記は不要です）。
- **未検証の扱い**: 未実施の項目は「未検証」と明記します。モック確認のみで実接続や保存などの検証完了とはみなしません。残課題は [PLAN.md](../PLAN.md) を参照してください。
