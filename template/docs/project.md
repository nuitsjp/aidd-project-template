## 4. 実現方法と確認した事実

{{DESIGN_AND_EVIDENCE}}

今回の機能に必要な設計内容を記入します（第3節と重複する仕様記述は避け、シナリオ ID で紐付けます）。

- **確認した事実**: 外部仕様や既存コードの調査結果（情報源・対象版・確認日・確認範囲）。仮定と明確に区別する。
- **責務と境界**: 実行・保存・信頼境界、処理の担当主体、状態更新の契機、結果確定点、障害時の停止・継続範囲（並行制御やトランザクション境界を含む）。
- **技術選定**: 言語・依存ライブラリ・モックツールの選定理由と、追加する仕組みに対する [判断基準](standards/design-and-documentation.md#design-decisions) の根拠。
- **モック設計**: モックで置き換える境界、再利用する本番処理、テストデータの配置、実処理への接続方法（モック対象外の場合は不要）。

<a id="verification"></a>
## 6. 検証結果

{{VERIFICATION_RESULTS}}

検証結果は本節に記録するか、既存の実行記録（テストレポートやCIログ等）を参照します。

- **記録項目**: 対象コード・版、実行環境、モック/実処理の別、実行日、コマンド、合否結果、ログ等の根拠。
- **参照時の補足**: 外部記録を参照する場合は、該当するシナリオ ID や受け入れ条件への対応と、受け入れ判断に必要な補足のみを記載します（自動テスト結果の手動転記は不要）。
- **未検証の扱い**: 未実施の項目は「未検証」と明記し、完了扱いにしてはなりません。モック確認のみで実接続や保存などの検証完了とみなすことは禁止します。残課題は [PLAN.md](../PLAN.md) を参照してください。
