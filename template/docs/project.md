## 3. ユースケースと合意

ユースケースは「1人の主アクターの1つの目的」単位とし、条件分岐を含まない主成功系列を1本定義します（API、画面、データ取得の単位では分割しません）。条件による差異は、主成功系列の途中から分岐する拡張系列として定義します（単独で目的を達成する系列は別ユースケースとし、拡張の本数を理由に分割しません）。拡張は着手する回に1本ずつ記述し、未着手の拡張を先回りして列挙しません。条件とメッセージだけが異なる場合は拡張を増やさず、条件と対応するメッセージを列挙します。利用者の操作・画面遷移・状態の変化が異なる場合のみ別の拡張とします。カタログ表の「モック適用」は、UI 確認が要の系列が1本以上あるユースケースを「対象」とします。
