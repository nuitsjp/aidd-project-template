<a id="design"></a>
## 4. 実現方法と確認した事実

{{DESIGN_AND_EVIDENCE}}

次のうち今回の機能に必要な内容を記入します。同じ事実や動作を第3節から転記せず、シナリオ ID で対応付けます。

- 外部仕様や既存コードから確認した事実、その情報源・対象版・確認日・確認範囲。未確認の仮定は区別する。
- 必要な実行・保存・信頼境界、担当する処理、状態を更新する主体、結果の確定点、失敗時の停止・継続範囲。競合・通信断・復旧がある場合は、並行制御と永続化のトランザクション境界も具体化する。該当しない観点はその理由を一言添える。
- 言語・依存関係・構成・モックツールの選択と、追加する仕組みに対する [判断基準](standards/design-and-documentation.md#design-decisions) の根拠。対象コードを特定する。
- モックで置き換える境界、再利用する本番側の処理、固定データの配置、実処理への接続方法。モック対象外なら不要。
