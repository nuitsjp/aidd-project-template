# 文書方針

本書は、標準の採用記録、モック駆動開発の適用範囲、正本の配置、および保護する合意を定義します。

<a id="adoption"></a>
## 1. 採用記録

導入状態: **未適用**。各項目を確定後に「適用済み」へ更新してください。

| 項目 | 内容 |
| --- | --- |
| 配布元・版 | `aidd-project-template` / 版2 |
| 設計・文書標準 | [project-template-design-and-documentation / 版2](standards/design-and-documentation.md) |
| モック標準 | [project-template-mock-driven-development / 版2](standards/mock-driven-development.md) |
| 採用日・判断者・合意の根拠 | {{ADOPTION_RECORD}} |
| プロジェクト固有の差分と理由 | {{LOCAL_RULE_DIFFERENCES}} |

採用後、設計・文書標準はすべての変更に適用されます。モック標準の適用範囲は第2節で定めます。固有の差分がない場合は「なし」と明記します。なお、テンプレートの新版は自動適用しません。

<a id="mock-scope"></a>
## 2. モック駆動開発の適用範囲

採用する対象・対象外とその理由: {{MOCK_SCOPE}}

- **対象の目安**: UIレイアウトや操作フロー、状態遷移など、動作確認を通じて合意を形成すべき新規機能や仕様変更を対象とします。画面のない機能（CLIやAPI等）でも、入出力仕様の合意が必要な場合は対象に含めます。
- **対象外の目安**: 確定済み仕様の不具合修正、振る舞いを変えない内部リファクタリング、文書修正など、動作確認による仕様合意が不要な作業は対象外とします（テストでのスタブ・モック利用とは区別します）。
- **記録方針**: モック駆動開発を採用しない場合はその理由を明記します。モックツールの選定内容は [プロジェクト定義](project.md#design) に記録します。

<a id="sources"></a>
## 3. 文書の役割と分割

| 正本 | 扱う内容 |
| --- | --- |
| 本書 | 標準の採用記録、正本の配置、保護する合意 |
| `standards/` 各標準 | プロジェクト非依存の開発・文書基準 |
| [project.md](project.md) | プロジェクトの目的・制約、仕様、設計判断、手順、検証結果 |
| 既存の検証記録 | テストレポートやCIログ等の外部証跡（利用する場合のみ） |
| [PLAN.md](../PLAN.md) | 作業進捗、作業順序、未決事項の管理 |
| [README.md](../README.md) | プロジェクト概要と参照案内 |
| [AGENTS.md](../AGENTS.md) | AIエージェントの作業規則 |

- **文書の分割基準**: 単独参照の必要性や更新頻度の違いにより管理が困難になった場合のみ正本を分割します。分割時は元の記述を参照に置き換え、本表および関連リンクを更新してください。
- **形式の柔軟性**: 図の形式や章構成は固定しません。プロジェクト固有で必須とする資料や観点がある場合は本節に記録します。

<a id="agreements"></a>
## 4. 保護する合意

採用した規則、適用範囲、正本の責務、および [プロジェクト定義](project.md) で合意済みの要件・制約・仕様・完了条件を保護対象とします。これらを変更・緩和する場合は、[標準の変更手続き](standards/design-and-documentation.md#agreement-changes) に従います。

なお、テンプレート初期の記入欄や検討中の案、モック上の仮定は合意済みとはみなしません。未確定事項は [PLAN.md](../PLAN.md) で管理します。
